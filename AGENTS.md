This guide applies to the Android Forwarder repository. Consult [RELEASE_2_1_6.md](RELEASE_2_1_6.md) for the 2026-11-15 Driver resilient phone entry and WorkManager REPLACE scheduling overhaul, [RELEASE_2_1_5.md](RELEASE_2_1_5.md) for the 2026-11-11 update/consent recovery and local Android16 verification, [RELEASE_2_1_4.md](RELEASE_2_1_4.md) for earlier publication and installation behavior, and [AUTOMATIC_ACTIVATION.md](AUTOMATIC_ACTIVATION.md) for protocol/source verification. Older README and activation sections are historical snapshots; confirm current code before using their HTTP, typed-phone, token or test-count statements.

As of version 2.1.6/code9, the Driver app provides dual activation paths:
1. **Primary direct manual phone entry**: The driver enters their 11-digit Iranian mobile number (`09xxxxxxxxx`) into `ManagedDriverScreen.kt` and taps "استعلام و فعال‌سازی شماره راننده". This performs an immediate, direct HTTPS resolution (`/api/v1/otp/resolve-driver` or enrollment) with the BarPro central server in under 1 second without requiring carrier bootstrap SMS transmission to the Hub.
2. **Fallback automatic carrier bootstrap**: If the driver's number is unknown, the "فعال‌سازی با شماره راننده یا سیم‌کارت" option remains available.
3. **WorkManager policy**: Background task scheduling in `DriverBootstrapWorker.kt` uses `ExistingWorkPolicy.REPLACE` (never `KEEP`), preventing no-op UI lockouts after transient network failures.

The Hub app (`APP_ROLE == "HUB"`) acts as the fleet gateway receiving and relaying verified driver OTP envelopes (`BP1#...`). A public Hub upgrade retains its stored private profile. A factory-clean Hub uses an organization-private, external one-use install capability, followed by a device-scoped credential. The private installer/profile is kept outside the public release and source tree; public tuning/update documents carry no credential. Source references are `HubInstallManager.kt`, `HubInstallRuntime.kt`, `HubInstallContract.kt`, `DriverActivationRuntime.kt`, `BootstrapSmsDispatch.kt` and `app/build.gradle.kts`.

Use the exact reviewed version properties for release builds and verify native APK versionCode/versionName, signer, debuggable flag and assets before delivery. The dated private build required both `--no-build-cache` and `--no-configuration-cache`. Keep the retained Android signer and ECDSA channel key backed up privately. Preserve valid private identities and explicit stop/consent decisions during recovery (`AutomaticEnrollmentRecoveryTest`, `MaintenanceConfigRaceTest`, `HubInstallActivationTest`).
